# Evidently 0.7.21 drift-monitoring baseline fixtures

Task: `ODP-NLTK-MONITORING-BASELINE-001`.
Consumed by: `tests/models/test_evidently_monitor_baseline.py`.

## What is in here

| Path | Content |
|---|---|
| `baseline_cases.py` | The only definition of the synthetic inputs, the column profiler and the normalizer. Imported by both the generator and the test suite, so a golden file can never describe inputs the test does not replay. |
| `generate_baseline.py` | Runner. Executes every case against the live pinned engine and writes the files below. `--check` regenerates in memory and diffs. |
| `manifest.json` | Provenance and input receipts: Python/OS, package versions, the repository SHA the run was made from, the RNG seed, the normalization policy, and per case the input row hashes, dtypes, cleaned `N` and merged unique counts, plus the SHA-256 of every file written. |
| `cases/<case_id>.raw.json` | The raw `evaluation.json()` string exactly as Evidently returned it. |
| `cases/<case_id>.golden.json` | The normalized contract: `EvidentlyDriftResult` fields, the full `to_dict()` payload, and a flattened per-column index of method / threshold / statistic. Cases that raise carry the exception type and message instead. |

Nothing here is hand-authored. Every number was read back from a live run.

## Regenerating

```bash
uv run --frozen --python 3.12 python tests/models/fixtures/evidently_0_7_21/generate_baseline.py
uv run --frozen --python 3.12 python tests/models/fixtures/evidently_0_7_21/generate_baseline.py --check
```

`--check` compares every case file byte for byte and every manifest key except
the four provenance keys (`generated_at`, `source_sha`, `source_branch`,
`source_worktree_clean`), which change on every run by construction.

The generator writes only inside this directory. It does not produce or touch an
SBOM, and it does not write into any `docs/evidence/completion/<other-task>` tree.

## Normalization

Exactly one field is normalized: `EvidentlyDriftResult.snapshot_id` when the
caller passed `snapshot_id=None`, because the wrapper then fills in
`f"evidently-{uuid4()}"`. The value is first validated against a uuid4-shaped
pattern and only then replaced by `<auto-generated-uuid4>`.

Never normalized: statistics, p-values, distances, method names, thresholds,
`drift_detected` / `drifted_columns` / `drift_share` / `drifted_column_names`,
category labels, column names, metric ids and ordering, and the type and message
of every refusal. `manifest.json["normalization"]` states this machine-readably
and a test asserts the policy has not been widened.

## Inputs

All inputs are synthetic and closed-form. No external data provider is called, no
NLP corpus or model is downloaded, and no secret or personal data appears. The
only randomness is `numpy.random.default_rng([20260906, stream])`, rounded to six
decimals so the fixtures stay byte-stable and readable.

## What a green run does and does not mean

It means the pinned engine still produces what it produced when these files were
written. It is not an equivalence proof for any replacement engine, and it is not
a security result: `evidently 0.7.21` still brings in the unpatched
`nltk 3.10.3`, and this suite neither changes nor consults any security gate.
