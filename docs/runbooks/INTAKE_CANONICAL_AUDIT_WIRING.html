Intake 業務交易與實體稽核接線

PostgreSQL factory 現在把 CanonicalPostgresAuditLog 接到 DurableAssistedIntakeStore。新增的 workflow_audits 與業務、outbox、成功 replay 使用同一個 engine/transaction 寫入 audit.audit_events；任何一步失敗共同 rollback。既有 Envelope 保留作為服務投影，不是獨立的稽核權威。

完成檢查會查詢真正的 canonical audit ID、內容與 event_sha256，不能只靠 Envelope 的成功／版本欄位。無實體紀錄、內容不一致或偽造 hash 皆不能完成。

政策與證據實作要求
正式 resolver讀取 workflow.decision_policies 的 intake_audit_retention 版本，核對有效／批准時間、tenant、目前帳戶狀態、scope 與實際 records_manager/retention_manager/compliance_officer role。沒有 runtime seeding 或 production retention 預設。
內部參數 v1schema_version=1、duration_basis=UTC_ELAPSED、正整數 retention_days；declared_inputs 必須列 scope、occurred_at。實際數值由正式 policy owner 批准供應。
不可改写版本0024/000030 是 expand-only policy kind migration，保留既有紀錄與兩個 Intake kind 的保護，新增 audit retention 同樣不可重寫／刪除；不建立批准或業務值。
绑定canonical audit.after_value 在原業務欄位旁加入 audit_retention_policy 證據，含版本、policy SHA、approved_by/at、deadline；由 event SHA 一起保護。這是 audited snapshot 的 metadata，沒有修改業務資源。保留 UUID actor、resource、before/after、sequence 與 policy binding。
缺失時回 503、DEPENDENCY_CONFLICT、reason AUDIT_POLICY_UNAVAILABLE、CONTACT_SUPPORT、retryable=false。沒有成功收據、部分業務或 audit。11 個 effective v1 operations 與 XLSX runtime extension 的 503 已宣告；此 additive overlay 修改待當前來源審查。

assisted_intake_audit_retention 是 trusted Python construction override，僅用明示 synthetic provider 驗證孤立 PG 測試；不是 request body、header 或環境中的 production bypass。正式預設一定從 SQL registry 讀取。

既有非法時間窗口測試初稿曾以 effective_to=effective_from 被 DB 正確拒絕，後改為有效的關閉窗口；另補齊舊 SQL fixture 缺少的新政策與必要 role，保留原 task/clock/crash/replay 斷言。

WORM URI 仍 NULL/worm_pending，沒有宣稱外部送達。Canonical Intake/Correction/Decision physical owner、Identity service 真正執行、歷史 mapping、非 workflow_audits 的全域安全稽核整合、正式六角色 UAT、規則／資料／模型與 release authority 仍須完成。本修補不是全系統上線准入。
