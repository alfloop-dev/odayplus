Intake policy／calendar adapter 工程契約

狀態：新增實作待獨立工程審查與 Workflow／Ops owner 確認。這份文件定義讀取格式，不批准業務數值、帳戶、租戶範圍或正式上線。

權威來源與 migration

PostgreSQL bundle 使用 SqlDecisionPolicyRepository 和 SqlIdentityStore，讀取現有 workflow.decision_policies、identity.accounts、角色與範圍。Alembic 0023 擴充政策種類限制並保護新增種類的版本內容，保留既有七種類並允許 intake_workflow、intake_business_calendar。新增兩種類的參數／批准／身份不能覆寫或刪除，有效期可關閉一次以 supersede；既有種類維持原行為；不新增政策、日曆、帳戶、授權或批准資料。正式 migration 執行須走既有發布流程。

版本 ID 必須是 registry 現存的 tenant-qualified ID。初始作業依提交時間解析政策；指派、暫停與恢復沿用該 SLA 記錄的確切政策與日曆版本。批准時間必須不晚於 governing timestamp；批准帳戶必須仍有效、屬於同租戶，持有記錄的 owner role，且允許 listing module 及工作所需的五個範圍軸。沒有有效紀錄時拒絕產生期限。

Intake policy parameters（schema_version = 1）

欄位工程解析規則權威資料責任
calendar_version_id、queue_key必填非空字串，日曆 ID 必須能解析Workflow／Ops 提供實際版本與 routing queue
warning_work_minutes、due_work_minutes、breach_work_minutes整數、非 bool；0 ≤ warning ≤ due ≤ breach，due > 0不得採用測試 fixture 的數值作正式政策
assignee_role_bindings請求 owner_role → canonical Role；目標帳戶必須實際持有該角色與工作範圍Identity／Workflow owner 確認 role mapping
deadline_override明確 KEEP_POLICY，或 BOUNDED_WORK_MINUTES 加 minimum_minutes、maximum_minutes、actor_roles。提議時間必須落在批准的工作量範圍並等於日曆 checkpoint不得由 UI 任意覆寫服務期限
approved_pause_reasons明確批准原因字串清單；請求原因必須吻合Workflow／Ops 確認清單與批准來源
declared_inputs（registry 欄位）初始化須含 scope、submitted_at；指派須另含 actor_account、target_account、requested_due_at治理紀錄須揭露實際使用輸入

Business calendar parameters（schema_version = 1）

欄位工程解析規則
timezone、coverage_from、coverage_through明確 IANA timezone 與 ISO 日期；區間不得反向，最多 3660 日的差值為資源防護，不是 SLA 時限
duration_basis必須明確 UTC_ELAPSED；計入真正工作區間經過的時間
weekly_windows必須明列字串鍵 1–7；每個值為 [[HH:MM, HH:MM], …]。空陣列表示關閉；區間不得重疊、為零或跨夜；結束可用 24:00
date_overrides必填 object，ISO 日期 → 當天完整工作區間；日期須落在 coverage；空陣列表示休假
ambiguous_time明確 EARLIER／LATER／REJECT；處理 DST 重複邊界
nonexistent_time必須明確 REJECT；不偷偷位移不存在的 DST 邊界

不預設時區、工作日、工作時間、午休或假日。工作量跨關閉區間時跳過它；超出已批准 coverage 時拒絕猜測期限。所有持久化 checkpoint 使用帶時區的 UTC。

暫停與恢復

HTTP 命令先檢查實際父 Intake 範圍，再檢查 If-Match、冪等鍵及仍有效的 manager／steward 帳戶。暫停原因必須被 policy 允許，expected_resume_at 必須在未來，已達 breach 的 SLA 即使狀態尚未更新也不能暫停。記錄區間 UUID、開始／預期恢復時間、原因、created_by、approved_by 與 approval_policy_version；自我批准被拒絕。

批准來源的工程限制：本 adapter 的 approved_by 來自已存在 policy 的批准帳戶，是批准原因清單的來源，不是新產生的人工作業核准。Workflow／Ops 必須確認這個映射符合正式 pause approval 規則；若需逐次批准紀錄，須另接實際批准工作流，不能把 policy 批准說成新的逐次批准。

恢復以服務時間關閉真實區間；排除該區間內的工作量，調整 warning／due／breach，並重新推導當前狀態。paused_duration_seconds 記錄實際暫停秒數，與日曆排除的工作秒數不同。Intake 與 Assignment 的期限變更一起增加版本並留下稽核。SLA 收據指向真正已寫入的 audit UUID。

命令、區間、稽核、catalog outbox event 與 replay receipt 屬於同一 rollback 邊界；失敗不保留成功重播。缺乏父 Intake 或權威 schedule 的舊封套拒絕操作，等待核准的對帳與遷移。這個交易邊界不包含需要保存失敗狀態的 SiteScore promotion saga。
