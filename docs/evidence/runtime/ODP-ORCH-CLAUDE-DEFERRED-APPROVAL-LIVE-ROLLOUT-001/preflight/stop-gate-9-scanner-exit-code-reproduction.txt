---------------------
The printed counts are identical under both scanners - detection was never the
problem and revision 10 changes none of it. The return code is the whole
finding:

  violating region   revision 9: rc=0   revision 10: rc=2
  clean region       revision 9: rc=0   revision 10: rc=0
  no sentinels       revision 9: rc=1   revision 10: rc=1

rc=0 on a region carrying ten bypasses is exactly what the docs claimed could
not happen, and it is what the committed STOP GATE 8 receipt recorded. A caller
writing the documented form - `probe_region_scan "$f" || fail` - would have read
revision 8's bypassed probe as clean. Revision 10 keeps the missing-sentinel
code at 1 and gives violations their own code, 2, so "there is no probe region
in this file" cannot be confused with "this probe region is bypassed".

this driver, a routed-only fixture, a both-bypasses fixture, a raw-only fixture,
a reader-only fixture and a file with no sentinels - instead of only the printed
counts: 63 -> 71 checks. See preflight/driver-gate-selftest.txt.
