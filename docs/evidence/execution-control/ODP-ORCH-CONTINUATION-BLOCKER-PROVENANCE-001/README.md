## Mechanism and trust boundary

Legacy/no-provenance tasks keep the existing keyword checks unchanged. No
negation parser or keyword deletion attempts to interpret "already done".
After normal independent review, merge and verified runtime adoption, only an
actual validated Human/Ops actor can record an explicit adjudication using the
normal `note` mechanism with `--blocker-provenance=<JSON>`:

```json
{
  "context_sha256": "<blocker_authority_digest of exact current task>",
  "expires_at": "<future timestamp>",
  "fields": {
    "next": [
      {"text": "<exact contiguous span>", "kind": "current", "reason": "<rationale>", "evidence_ref": "<readback receipt>"},
      {"text": "<next exact span>", "kind": "resolved", "reason": "<explicit completed prerequisite determination>", "evidence_ref": "<readback receipt>"}
    ]
  }
}
```

Each classified field must be covered completely by ordered spans whose text
concatenates byte-for-byte to the original field. Kinds are `current`, `resolved`,
`historical`, `other_task`; the latter additionally requires a distinct `task_id`.
Every span needs rationale and an evidence reference. The human adjudicator is
responsible for verifying those referenced receipts; the program does not infer
receipt truth, scope or human authority from their wording. Ambiguous evidence
must remain `current` (or unclassified), never default to resolved.

The command requires explicit blocked Human/Ops review-churn escalation. It
rejects AI actors, malformed payloads, partial coverage, unknown kinds and
stale/expired binding before mutation. Issuer/time/record id are generated by
the command, not accepted from the caller. It leaves next, status, waiting_for,
roles, findings, counters and approvals unchanged, archives earlier adjudications
and logs the full new record. Ordinary notes cannot act as adjudications.

The context digest binds all blocker-facing fields, task id/status, owner and
reviewer, source submission, independent fields, review history and escalation
epoch. Subsequent changes invalidate adjudication. Current spans and every
unclassified field still undergo the legacy prose gate. Explicit independent
gate fields always refuse regardless of classification. Invalid/stale provenance
fails closed even if current prose otherwise looks harmless. Existing source
identifier/path/CI-job regression behavior is preserved.

A provenance record only determines blocker attribution for eligibility. It is
not consent to execute, deployment approval, or a continuation approval. The
separate existing Human/Ops continuation command still issues a task-scoped,
expiring nonce. New approvals additionally bind the blocker digest and provenance
record id; re-adjudication, source/epoch/text changes, wrong task, AI issuer,
expiration or consumed state refuse validation. Existing nonce registry/history
replay protection and supervisor single-consumption transition remain unchanged.
Supervisor consumes through `runtime_ai_status.continuation_approval_validation_error`;
no alternate dispatch path or recovery policy was added.
